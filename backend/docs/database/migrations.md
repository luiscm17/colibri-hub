# Migration Strategy

Database schema management for Colibri Hub uses the Supabase CLI exclusively.
This decision is documented in
[ADR-001: Supabase CLI for Database Migrations](../../../docs/architecture/decisions/001-supabase-migrations.md).

---

## 1. Migration Tool

All schema changes are managed through the Supabase CLI. There is no Alembic
setup — SQLAlchemy ORM mappings are declarative mirrors of the migration state,
not generators of it.

Migrations are the **physical authority** for the database schema.

## 2. Migration File Convention

Migration files live under `supabase/migrations/` with timestamped filenames
generated by the CLI:

```
supabase/migrations/<YYYYMMDDHHmmss>_<descriptive_name>.sql
```

Example:

```
supabase/migrations/20260722130455_create_raw_material_reception_storage.sql
```

Each file contains imperative SQL. Migrations are forward-only — there is no
built-in rollback mechanism.

## 3. Workflow

### Generate a New Migration

```bash
pnpm supabase migration new <descriptive-name>
```

This creates an empty timestamped SQL file.

### Write the Migration

Write DDL statements directly in the generated file. Conventions:

- Use named constraints (`uq_`, `ck_`, `pk_`, `fk_`, `idx_` prefixes)
- Enable RLS on new tables
- Revoke default privileges from `anon`, `authenticated`, `service_role`
- Use `NUMERIC` for decimal values (weights, Dtex)
- Keep `UUID` primary keys with `gen_random_uuid()` defaults

### Apply Locally

```bash
pnpm supabase db reset --local --no-seed
```

`--no-seed` is required because `supabase/config.toml` references
`supabase/seed.sql`, which does not exist.

### Verify Migration State

```bash
pnpm supabase migration list --local
```

### Deploy to Remote

Migrations are applied on `supabase db push` or through CI on the remote
project.

## 4. Local Development Setup

Prerequisites:

- Supabase CLI (via pnpm wrapper)
- Docker-compatible runtime

```bash
pnpm supabase start
pnpm supabase db reset --local --no-seed
```

This provisions a local PostgreSQL instance on port `54322` with all migrations
applied.

## 5. Integration Testing

Integration tests connect to the local Supabase PostgreSQL instance:

```bash
TEST_DATABASE_URL=postgresql+psycopg://postgres:postgres@127.0.0.1:54322/postgres \
  uv run --locked python -m unittest discover -s backend/integration_tests -v
```

Tests deliberately accept only `postgresql+psycopg` URLs on loopback port
`54322`, database `postgres`.

## 6. ORM Alignment

SQLAlchemy models must reflect the current migration state. The ORM does not
generate migrations — it is a consumer of the schema defined by migrations.
When adding columns or tables:

1. Write the migration SQL first
2. Update the ORM model to match
3. Verify with integration tests against local PostgreSQL
